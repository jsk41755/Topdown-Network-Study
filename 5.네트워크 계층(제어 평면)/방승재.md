- 논리적 중앙 집중형 제어를 기반으로 하는 제어 평면이란 무슨 뜻인가? 왜 ‘논리적’ 중앙 집중형이라고 하는가?

  <details>
  <summary>정답 보기</summary>

  ### 1. 기존의 라우터별 제어 방식
  전통적인 네트워크에서는 각 라우터 안에 데이터 평면과 제어 평면이 함께 있습니다.

    ```
    Router A                Router B
    ┌──────────────┐       ┌──────────────┐
    │ 제어 평면      │◀─────▶│ 제어 평면       │
    │ OSPF/BGP     │       │ OSPF/BGP     │
    ├──────────────┤       ├──────────────┤
    │ 데이터 평면     │       │ 데이터 평면     │
    │ 패킷 포워딩     │       │ 패킷 포워딩     │
    └──────────────┘       └──────────────┘
    ```

  따라서 제어가 **분산되어 있고**, 각 라우터가 어느 정도 독립적인 의사결정 주체입니다.

  ### 2. 논리적 중앙 집중형 제어 방식

  SDN과 같은 구조에서는 경로 계산과 정책 결정이 라우터 또는 스위치 외부의 컨트롤러로 이동합니다.

    ```
                    SDN Controller
              ┌──────────────────────┐
              │ 네트워크 전체 상태 관리 │
              │ 경로 및 정책 계산       │
              │ 포워딩 규칙 생성        │
              └───────┬───────┬──────┘
                      │       │
              ┌───────▼──┐ ┌──▼────────┐
              │ Switch A │ │ Switch B  │
              │ 데이터 평면│ │ 데이터 평면 │
              └──────────┘ └───────────┘
    ```

  ### 3. 왜 ‘논리적’ 중앙 집중형이라고 하는가?

  컨트롤러가 반드시 물리적인 서버 한 대라는 뜻은 아닙니다.

    ```
                     하나의 논리적 컨트롤러
                               │
                 ┌─────────────┼─────────────┐
                 │             │             │
            Controller 1  Controller 2  Controller 3
    ```

  실제 환경에서는 장애 대응과 확장성을 위해 여러 서버에 컨트롤러를 분산할 수 있습니다.

  그러나 스위치나 제어 애플리케이션 입장에서는 하나의 통합된 제어 시스템처럼 보입니다.

    ```
    물리적으로는 분산될 수 있음
    논리적으로는 하나의 중앙 컨트롤러처럼 동작
    ```

- 인터넷에의 AS 간 라우팅과 AS 내부 라우팅에는 왜 각기 다른 프로토콜을 사용하는가?

  <details>
  <summary>정답 보기</summary>

  AS 내부: 하나의 조직이 관리하므로 **빠르고 효율적인 경로**가 중요

  AS 간: 서로 다른 조직이 연결되므로 **정책과 사업 관계를 반영하는 경로**가 중요

  예를 들어 OSPF는 링크 비용을 사용하여 다음과 같은 경로를 계산합니다.

    ```
    경로 1: R1 → R2 → R4, 비용 20
    경로 2: R1 → R3 → R4, 비용 50
    ```

  따라서 비용이 작은 경로 1을 선택합니다.

  반면 AS 간에서는 반드시 가장 짧거나 빠른 경로를 선택하지 않습니다.

    ```
    AS 100 ─ AS 200 ─ 목적지
       \
        AS 300 ─ AS 400 ─ 목적지
    ```

  AS 100의 입장에서는 AS 200을 거치는 경로가 더 짧을 수 있습니다. 그러나 다음과 같은 이유로 더 긴 AS 300 경로를 선택할 수도 있습니다.

    - AS 200 경로는 비용이 비쌈
    - AS 300은 계약된 고객 또는 파트너
    - 특정 국가나 사업자의 네트워크를 피해야 함
    - 보안이나 규제 정책을 따라야 함
    - 다른 AS의 트래픽을 무료로 중계하고 싶지 않음

  즉, AS 간 라우팅은 다음과 같이 동작합니다.

  > 가장 짧은 경로가 아니라, 해당 AS의 정책에 가장 적합한 경로를 선택한다.
  >

  </details>

- OpenDaylight SDN 컨트롤러의 서비스 추상화 계층의 목적은 무엇인가?

  <details>
  <summary>정답 보기</summary>

  컨트롤러 애플리케이션과 실제 네트워크 장비·프로토콜 사이의 차이를 숨기고, 애플리케이션이 공통된 방식으로 네트워크를 제어할 수 있도록 하는 것입니다.

  ## OpenDaylight의 구조

  대략 다음과 같은 계층으로 볼 수 있습니다.

    ```
    ┌─────────────────────────────┐
    │ SDN 애플리케이션             │
    │ 라우팅, 방화벽, 부하 분산 등  │
    └──────────────┬──────────────┘
                   │ 공통 API
    ┌──────────────▼──────────────┐
    │ 서비스 추상화 계층(SAL)       │
    └──────────────┬──────────────┘
                   │
    ┌──────────────▼──────────────┐
    │ Southbound 플러그인           │
    │ OpenFlow, NETCONF, BGP 등     │
    └──────────────┬──────────────┘
                   │
    ┌──────────────▼──────────────┐
    │ 실제 스위치·라우터            │
    └─────────────────────────────┘
    ```

    1. 장비와 프로토콜의 차이를 숨긴다.
    2. 애플리케이션과 네트워크 장비를 느슨하게 결합한다.

    ```
    애플리케이션
        ↓
    SAL
        ↓
    OpenFlow 플러그인 또는 NETCONF 플러그인
    ```

    3. 네트워크 정보를 공통 모델로 표현한다.
    4. 새로운 프로토콜과 장비를 쉽게 추가한다.

  </details>
