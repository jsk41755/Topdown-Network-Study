<summary><strong>질문 1. Wi-Fi MAC 주소는 어떤 Wi-Fi에 연결하느냐에 따라 달라질까?</strong></summary>

짧게 답하면 다음과 같다.

> 기기에 원래 들어 있는 Wi-Fi 인터페이스의 하드웨어 MAC 주소는 AP에 따라 바뀌지 않는다. 하지만 최신 기기는 개인정보 보호를 위해 Wi-Fi 네트워크별로 다른 랜덤 MAC 주소를 사용할 수 있다.

### 원래의 하드웨어 MAC 주소

스마트폰에는 Wi-Fi 통신을 담당하는 네트워크 인터페이스가 있고, 이 인터페이스에는 기본 MAC 주소가 있다.

```text
스마트폰의 Wi-Fi 인터페이스
└─ 기본 MAC: AA:AA:AA:AA:AA:AA
```

개인정보 보호 기능을 사용하지 않는다고 가정하면 어떤 AP에 연결해도 기본 MAC 주소는 같다.

```text
집 Wi-Fi 연결     → AA:AA:AA:AA:AA:AA
학교 Wi-Fi 연결   → AA:AA:AA:AA:AA:AA
카페 Wi-Fi 연결   → AA:AA:AA:AA:AA:AA
```

### 랜덤 MAC·비공개 MAC 주소

항상 같은 MAC 주소를 사용하면 여러 장소의 AP가 같은 기기를 알아보고 이동 경로를 추적할 수 있다.

이를 막기 위해 최신 운영체제는 실제 하드웨어 MAC 대신 임의로 만든 **랜덤 MAC** 또는 **비공개 MAC**을 사용할 수 있다.

```text
실제 하드웨어 MAC
AA:AA:AA:AA:AA:AA

집 Wi-Fi에서 보이는 MAC
12:34:56:78:90:01

학교 Wi-Fi에서 보이는 MAC
98:76:54:32:10:02
```

따라서 AP가 기기의 MAC 주소를 바꾸는 것이 아니다. **기기가 연결할 네트워크에 맞추어 다른 주소를 선택해서 AP에 보여주는 것**이다.

랜덤 MAC이 언제 바뀌는지는 운영체제와 설정에 따라 다르다.

- 같은 Wi-Fi 네트워크에서는 일정 기간 같은 랜덤 MAC을 사용할 수 있다.
- 다른 Wi-Fi 네트워크에서는 다른 랜덤 MAC을 사용할 수 있다.
- 네트워크 설정을 삭제하거나 개인정보 보호 설정을 바꾸면 주소가 달라질 수 있다.
- 일부 환경에서는 시간이 지나면 주소가 다시 변경될 수도 있다.

### 앱 개발자가 알아둘 점

MAC 주소를 사용자를 식별하는 영구 ID로 사용하면 안 된다.

- 네트워크마다 다른 MAC이 보일 수 있다.
- 개인정보 보호 기능 때문에 MAC이 바뀔 수 있다.
- 앱이 실제 Wi-Fi MAC 주소에 접근하는 것도 운영체제에서 제한될 수 있다.
- 한 사용자가 기기를 바꾸거나 네트워크 설정을 초기화할 수도 있다.

사용자나 설치를 식별해야 한다면 로그인 계정, 서버가 발급한 식별자, 운영체제가 허용하는 앱 범위 식별자 등 목적에 맞는 방법을 사용해야 한다.

### AP에도 MAC 주소가 있다

스마트폰만 MAC 주소를 갖는 것은 아니다. AP의 무선 인터페이스도 MAC 주소를 가지며, AP를 구별하는 데 사용되는 주소를 보통 **BSSID**라고 한다.

```text
SSID: School_WiFi

1층 AP의 BSSID: 10:10:10:10:10:01
2층 AP의 BSSID: 10:10:10:10:10:02
3층 AP의 BSSID: 10:10:10:10:10:03
```

여러 AP가 같은 SSID를 제공해도 BSSID는 서로 다를 수 있다.

### 정리

| 구분 | 의미 | Wi-Fi가 바뀌면? |
|---|---|---|
| 하드웨어 MAC | Wi-Fi 인터페이스의 기본 주소 | 원칙적으로 그대로 |
| 랜덤·비공개 MAC | 추적 방지를 위해 기기가 만든 주소 | 네트워크별로 달라질 수 있음 |
| BSSID | 현재 AP의 무선 인터페이스 주소 | 다른 AP로 이동하면 달라질 수 있음 |

> “내 기기의 기본 MAC이 바뀐다”기보다 “기기가 네트워크마다 다른 랜덤 MAC을 보여줄 수 있고, 연결한 AP의 BSSID도 달라진다”가 정확한 표현이다.

<summary><strong>질문 2. Wi-Fi는 왜 충돌을 발견하기보다 피하려고 할까?</strong></summary>

유선 네트워크에서는 데이터를 보내면서 충돌이 일어났는지 비교적 쉽게 확인할 수 있다.

하지만 무선 장치는 자신이 내보내는 강한 신호 때문에 다른 장치의 약한 신호를 동시에 듣기 어렵다. 서로의 신호를 듣지 못하는 숨은 터미널 문제도 있어서 전송 중 충돌을 정확히 알아내기 힘들다.

그래서 Wi-Fi는 **CSMA/CA**를 사용한다. 먼저 채널이 비었는지 확인하고, 무작위로 잠깐 기다린 뒤 데이터를 보낸다. 필요한 경우 RTS/CTS로 채널을 예약해 충돌 가능성을 더 줄인다.

> Wi-Fi는 충돌을 발견해서 멈추기보다 전송 전에 충돌할 가능성을 낮춘다.

</details>

<details>
<summary><strong>질문 3. 이동 중 기지국이 바뀌어도 통신은 어떻게 이어질까?</strong></summary>

스마트폰이 한 기지국의 범위를 벗어나면 네트워크는 **핸드오버**를 진행한다.

1. 스마트폰이 주변 기지국의 신호를 측정한다.
2. 네트워크가 다음 기지국을 고르고 필요한 자원을 준비한다.
3. 스마트폰이 새 기지국에 연결한다.
4. 이전 기지국에 남은 데이터를 새 기지국으로 전달한다.
5. 코어 네트워크가 데이터가 지나가는 터널의 끝을 새 기지국으로 바꾼다.

즉, 스마트폰의 연결 지점만 바뀌는 것이 아니라 네트워크 내부의 데이터 경로도 함께 바뀌기 때문에 통신을 계속 이어갈 수 있다.

다만 핸드오버 중에는 지연이나 패킷 손실이 생길 수 있다. 앱은 일시적인 끊김, 재시도, 네트워크 변경을 정상적인 상황으로 처리해야 한다.

</details>


# 7.1 무선 네트워크 개요

## 무선 네트워크의 구성 요소

### 무선 호스트

무선으로 통신하는 종단 장치다.

- 스마트폰
- 노트북과 태블릿
- 스마트워치
- 자동차
- 센서와 각종 IoT 기기

유선 컴퓨터와 역할은 같지만, 랜선 대신 전파를 이용한다.

### 무선 링크

장치와 장치 사이에서 전파가 이동하는 통신 길이다.

```text
스마트폰 ))) 무선 링크 ))) Wi-Fi 공유기
```

무선 링크는 벽, 거리, 다른 전파 등의 영향을 많이 받는다.

### 기지국

여러 무선 장치를 네트워크에 연결해주는 중간 관리자다.

- Wi-Fi에서는 AP(Access Point)
- 셀룰러 네트워크에서는 셀 타워 또는 기지국

학교로 비유하면 학생들이 교문을 통해 학교 밖으로 나가는 것과 같다. 무선 장치는 보통 기지국을 통해 더 큰 네트워크와 통신한다.

### 결합

무선 장치가 특정 기지국을 자신의 연결 지점으로 선택하는 것이다.

스마트폰이 집 Wi-Fi에 연결되었다면 다음 조건이 만족된 것이다.

1. 스마트폰이 공유기의 전파 범위 안에 있다.
2. 스마트폰이 그 공유기를 통해 인터넷과 통신한다.

### 네트워크 인프라스트럭처

무선 장치가 AP나 기지국을 통해 접속하려는 더 큰 네트워크다. 공유기 뒤의 유선망이나 통신사의 코어 네트워크, 인터넷 등이 여기에 해당한다.

### 인프라스트럭처 방식과 애드혹 방식

- **인프라스트럭처 방식:** AP나 기지국이 통신을 중개한다.
- **애드혹 방식:** 중앙 기지국 없이 장치끼리 직접 통신한다.

```text
인프라 방식: 스마트폰 → 공유기 → 인터넷
애드혹 방식: 스마트폰 ↔ 노트북
```

### 핸드오버

이동 중에 현재 기지국에서 다른 기지국으로 연결을 넘기는 과정이다. 핸드오프라고도 한다.

통화하면서 자동차로 이동해도 통화가 계속되는 것은 통신사가 연결을 다음 기지국으로 넘겨주기 때문이다.

```text
기지국 A ← 스마트폰 이동 → 기지국 B
             핸드오버
```

## 홉이란?

**홉(hop)**은 데이터가 한 장치에서 바로 다음 장치로 한 번 이동하는 것이다.

징검다리에서 다음 돌로 한 번 점프하는 것을 1홉이라고 생각하면 쉽다.

```text
내 노트북 → 공유기 → 통신사 라우터 → 서버
          1홉       2홉              3홉
```

- **단일 홉:** 중간 무선 장치를 거치지 않고 한 번에 도착
- **다중 홉:** 여러 장치가 데이터를 차례로 중계

```text
단일 홉: 스마트폰 → Wi-Fi 공유기
다중 홉: 장치 A → 장치 B → 장치 C → 기지국
```

즉, 홉 수는 데이터가 목적지까지 가며 장치 사이를 몇 번 건너갔는지를 나타낸다.

## 무선 네트워크의 네 가지 종류

분류 기준은 두 가지다.

1. 목적지까지 무선 구간을 한 번만 지나는가, 여러 번 지나는가?
2. AP나 기지국 같은 인프라가 있는가?

| 종류 | 쉬운 설명 | 예 |
|---|---|---|
| 단일 홉 + 인프라 있음 | 기지국에 바로 연결 | Wi-Fi, LTE |
| 단일 홉 + 인프라 없음 | 장치끼리 바로 연결 | 블루투스 |
| 다중 홉 + 인프라 있음 | 다른 장치가 기지국까지 중계 | 무선 메시 네트워크 |
| 다중 홉 + 인프라 없음 | 기지국 없이 장치들이 중계 | MANET |

# 7.2 무선 링크와 네트워크의 특징

유선에서는 신호가 케이블 안으로 이동하지만, 무선 신호는 공기 중으로 퍼진다. 그래서 무선에서는 오류가 더 자주 발생한다.

## 경로 손실

송신자와 수신자 사이의 거리가 멀어질수록 신호가 약해지는 현상이다. 멀리 있는 사람의 목소리가 작게 들리는 것과 같다.

벽이나 건물 같은 장애물을 통과하면 신호는 더 약해진다.

## 간섭

같거나 비슷한 주파수를 사용하는 장치들이 서로의 통신을 방해하는 현상이다.

2.4GHz 대역에서는 Wi-Fi, 블루투스, 전자레인지, 무선 전화기 등이 서로 영향을 줄 수 있다. 여러 사람이 동시에 말하면 목소리가 섞이는 것과 같다.

## 다중 경로 전파

하나의 신호가 벽, 바닥, 건물 등에 반사되어 여러 길로 수신자에게 도착하는 현상이다.

```text
송신자 ─────────────→ 수신자
   └→ 벽에 반사 ────→ 수신자
   └→ 바닥에 반사 ──→ 수신자
```

서로 다른 시간에 신호의 여러 복사본이 도착하기 때문에 원래 신호를 정확히 알아보기 어려워진다.

## SNR과 BER

### SNR

신호와 잡음의 비율이다.

- **신호:** 내가 듣고 싶은 목소리
- **잡음:** 주변 사람들의 대화와 소음

SNR이 높다는 것은 원하는 신호가 잡음보다 강하다는 뜻이다.

```text
SNR 높음 → 신호가 또렷함
SNR 낮음 → 신호가 잡음에 묻힘
```

### BER

전송한 비트가 잘못 전달될 확률이다.

```text
보낸 비트: 1 0 1 1
받은 비트: 1 0 0 1
              ↑ 오류
```

일반적으로 다음 관계가 성립한다.

```text
SNR 증가 → BER 감소
SNR 감소 → BER 증가
```

그러나 신호 출력을 무조건 높일 수는 없다.

- 배터리가 빨리 소모된다.
- 다른 장치에 더 큰 간섭을 준다.
- 일정 수준 이상에서는 추가 효과가 작다.

## 전송 속도와 오류율

신호가 좋을 때는 복잡한 변조 기법으로 한 번에 많은 데이터를 보낼 수 있다. 신호가 나쁠 때는 느리더라도 단순하고 안전한 방식을 사용해야 한다.

```text
신호 좋음 → 빠른 전송 방식
신호 나쁨 → 느리지만 오류에 강한 방식
```

Wi-Fi와 셀룰러 네트워크가 환경에 따라 전송 속도를 자동으로 조절하는 이유다.

## 숨은 터미널 문제

A와 C가 서로의 신호는 듣지 못하지만 둘 다 B에게 전송할 수 있는 상황이다.

```text
A ))) B ((( C

A와 C는 서로 보이지 않지만
B에서는 두 신호가 충돌한다.
```

A와 C는 상대가 전송 중이라는 사실을 모르기 때문에 둘 다 채널이 비어 있다고 착각할 수 있다.

### 숨은 터미널 문제는 어떻게 해결할까?

대표적인 해결 방법은 Wi-Fi의 **RTS/CTS를 이용한 채널 예약**이다.

```text
A: “B에게 데이터를 보내도 될까요?” ── RTS ──→ B

B: “A가 보낼 예정이니 다른 장치는 기다리세요.”
   ── CTS ──→ A와 C를 포함한 주변 장치

A: ── DATA ──→ B
B: ── ACK  ──→ A
```

진행 과정은 다음과 같다.

1. A가 긴 데이터를 바로 보내지 않고, 짧은 `RTS(Request to Send)`를 B에게 먼저 보낸다.
2. B는 A에게 `CTS(Clear to Send)`를 보낸다. 무선 신호이기 때문에 B 주변의 C도 이 CTS를 들을 수 있다.
3. A는 CTS를 받으면 데이터를 전송한다.
4. C도 A의 신호는 듣지 못하지만 **B가 보낸 CTS는 들을 수 있으므로**, 예약된 시간 동안 기다린다.
5. B가 데이터를 정상적으로 받으면 A에게 ACK를 보낸다.

핵심은 A와 C가 서로를 직접 발견하게 만드는 것이 아니다.

> 두 장치가 모두 들을 수 있는 중간 수신자 B가 교통정리를 하게 만드는 것이다.

RTS와 CTS는 DATA 프레임보다 짧다. 따라서 A와 C의 RTS가 우연히 충돌하더라도 긴 DATA 프레임 전체가 충돌하는 것보다 낭비가 작다. 충돌한 장치는 랜덤 백오프 후 다시 시도한다.

### RTS/CTS를 항상 사용하지 않는 이유

RTS와 CTS도 전송 시간이 필요한 별도의 프레임이다. 작은 데이터를 보낼 때마다 아래 네 단계를 모두 수행하면 오히려 느려질 수 있다.

```text
RTS → CTS → DATA → ACK
```

따라서 일반적으로 프레임이 설정된 **RTS 임계값보다 클 때만** RTS/CTS를 사용한다.

### 완전히 해결되는 것은 아니다

RTS/CTS는 숨은 터미널 문제를 없애기보다 충돌 가능성과 충돌 비용을 줄이는 방법이다.

- RTS끼리도 충돌할 수 있다.
- 모든 장치가 CTS를 안정적으로 듣는다는 보장이 없다.
- 제어 프레임 때문에 추가 지연이 생긴다.

실제 무선 네트워크에서는 다음 방법도 함께 사용한다.

- 랜덤 백오프로 장치들의 전송 시점을 분산
- 서로 겹치지 않는 Wi-Fi 채널 사용
- AP 위치와 송신 출력을 조절해 음영 지역 감소
- 긴 데이터를 작은 프레임으로 나누어 충돌 비용 감소
- 지향성 안테나나 빔포밍으로 불필요한 간섭 감소

한 문장으로 정리하면 다음과 같다.

> 숨은 터미널 문제는 RTS/CTS로 수신자가 채널을 예약하고 주변 장치를 잠시 기다리게 하여 완화한다.

## 페이딩

장애물, 거리, 이동 등의 영향으로 신호의 세기가 약해지거나 계속 변하는 현상이다. 같은 장소에서도 사람이나 문이 움직이면 Wi-Fi 신호가 달라질 수 있다.

## 7.2.1 CDMA

CDMA는 여러 사용자가 같은 시간과 같은 주파수를 사용하되 서로 다른 코드를 사용하는 방식이다.

교실에서 여러 학생이 동시에 말하지만 각자 다른 언어를 사용한다고 생각할 수 있다. 수신자가 원하는 언어를 알고 있다면 특정 학생의 말만 골라낼 수 있다.

```text
사용자 A → 코드 A로 데이터 변환
사용자 B → 코드 B로 데이터 변환
사용자 C → 코드 C로 데이터 변환

수신자 → 코드 A를 이용해 A의 데이터만 추출
```

> CDMA는 시간이나 주파수를 나누는 대신 코드를 나누어 여러 사용자를 구별한다.

# 7.3 Wi-Fi: IEEE 802.11 무선 LAN

Wi-Fi의 정식 표준 이름은 **IEEE 802.11**이다.

`802.11n`, `802.11ac`, `802.11ax` 등은 서로 다른 세대의 Wi-Fi 표준이다. 새로운 세대로 갈수록 일반적으로 속도, 동시 사용자 처리 능력, 효율이 좋아진다.

## 주파수 대역

| 구분 | 장점 | 단점 |
|---|---|---|
| 2.4GHz | 비교적 멀리 가고 벽을 잘 통과함 | 간섭이 많고 혼잡함 |
| 5GHz | 넓은 채널과 빠른 통신에 유리함 | 도달 거리가 짧고 장애물에 약함 |

## MIMO

여러 안테나를 사용해 데이터를 동시에 송수신하는 기술이다. 여러 차선을 동시에 사용하는 것과 비슷하다.

## 7.3.1 Wi-Fi의 구조

### AP란?

**AP(Access Point)**는 스마트폰이나 노트북 같은 무선 장치를 유선 네트워크에 연결해주는 **무선 접속 지점**이다.

```text
스마트폰 ))) AP ─── 유선 네트워크 ─── 인터넷
            ↑
      무선과 유선을 이어주는 다리
```

학교 건물의 출입문으로 비유할 수 있다. 무선 장치는 AP라는 출입문을 거쳐 학교 내부 네트워크나 인터넷으로 나간다.

### AP가 하는 일

- 주변에 비컨 프레임을 보내 자신의 존재와 SSID를 알린다.
- 무선 장치의 결합 요청을 받아 연결을 맺는다.
- 필요하면 비밀번호 등을 이용한 인증 과정을 중계한다.
- 무선 장치가 보낸 802.11 프레임을 유선 이더넷 쪽으로 전달한다.
- 유선망에서 온 프레임을 해당 무선 장치로 전달한다.
- 여러 무선 장치가 하나의 채널을 나누어 사용할 수 있게 돕는다.
- 잠든 무선 장치로 향하는 프레임을 잠시 보관할 수 있다.

### AP와 공유기는 같은 것일까?

엄밀히 말하면 다르다.

| 장치 | 주요 역할 |
|---|---|
| AP | 무선 장치를 유선 LAN에 연결 |
| 스위치 | 같은 LAN 안에서 프레임 전달 |
| 라우터 | 서로 다른 IP 네트워크 사이에서 패킷 전달 |
| DHCP 서버 | 장치에 IP 주소와 네트워크 설정 제공 |
| NAT 장치 | 사설 IP 주소와 공인 IP 주소 사이를 변환 |

가정용 **Wi-Fi 공유기 한 대**에는 보통 이 기능들이 함께 들어 있다.

```text
가정용 Wi-Fi 공유기
├─ AP 기능
├─ 라우터 기능
├─ 이더넷 스위치 기능
├─ DHCP 서버 기능
└─ NAT·방화벽 기능
```

따라서 집에서는 AP와 공유기를 거의 같은 뜻으로 말하기도 한다. 하지만 회사나 학교에서는 AP와 라우터가 별도의 장비인 경우가 많다.

```text
회사·학교의 예

스마트폰 ))) AP ─── 스위치 ─── 라우터 ─── 인터넷
```

### AP는 IP 라우팅을 하는 장치일까?

순수한 AP는 기본적으로 **링크 계층의 다리(브리지)** 역할을 한다.

```text
Wi-Fi의 802.11 프레임
          ↓ AP가 변환·전달
유선 LAN의 이더넷 프레임
```

AP는 무선 장치와 유선 LAN 사이에서 프레임을 전달한다. 서로 다른 IP 네트워크 사이의 길을 고르는 라우팅은 보통 라우터가 담당한다.

다만 가정용 공유기는 AP와 라우터 기능을 한 장비에 합쳐 놓았기 때문에 둘의 역할이 눈에 잘 구분되지 않는다.

### BSS

Wi-Fi 네트워크의 가장 기본적인 단위다.

- 하나의 AP
- AP에 연결된 여러 무선 장치

```text
           노트북
              \
스마트폰 ———— AP ———— 인터넷
              /
            태블릿
```

### SSID

사용자에게 보이는 Wi-Fi 이름이다.

```text
우리집_WiFi
School_Guest
CoffeeShop_5G
```

SSID가 같다고 해서 반드시 하나의 AP만 존재하는 것은 아니다. 회사나 학교에서는 여러 AP가 같은 SSID를 사용할 수 있다.

### 채널

하나의 주파수 대역을 나눈 작은 통신 구간이다. 가까운 AP들이 겹치는 채널을 사용하면 서로 간섭할 수 있다.

### Wi-Fi 정글

한 장소에서 여러 AP의 신호가 동시에 잡히는 환경이다. 스마트폰은 그중 하나를 선택해 결합해야 한다.

### 수동 스캐닝

AP가 주기적으로 보내는 비컨 프레임을 무선 장치가 기다리는 방식이다.

```text
AP: “내 이름은 School_WiFi이고 여기 있어!”
스마트폰: 비컨을 듣고 AP 발견
```

### 능동 스캐닝

무선 장치가 주변 AP를 찾는 프로브 요청을 먼저 방송하는 방식이다.

```text
스마트폰: “주변에 Wi-Fi 있나요?”
AP들: “여기 있습니다!”
```

AP를 고른 뒤에는 결합과 인증을 거치고, DHCP로 IP 주소를 받을 수 있다.

## 7.3.2 Wi-Fi의 MAC 프로토콜

여러 무선 장치가 하나의 채널을 공유하기 때문에 누가 언제 보낼지 정해야 한다. Wi-Fi는 **CSMA/CA**를 사용한다.

### CSMA/CA

- **CS:** 전송 전에 채널이 사용 중인지 확인
- **MA:** 여러 장치가 하나의 채널을 함께 사용
- **CA:** 충돌을 피하려고 노력

기본 과정은 다음과 같다.

1. 채널이 사용 중인지 확인한다.
2. 사용 중이면 기다린다.
3. 채널이 비면 임의의 대기 시간을 고른다.
4. 대기 시간이 0이 되면 전송한다.
5. 수신자의 ACK를 기다린다.
6. ACK가 없으면 다시 시도한다.

### 충돌 검출 대신 충돌 회피를 사용하는 이유

무선 장치는 자신이 보내는 강한 신호 때문에 다른 장치의 약한 신호를 동시에 듣기 어렵다. 숨은 터미널 문제도 있기 때문에 전송 중 충돌을 정확히 알아내기 어렵다.

> Wi-Fi는 충돌을 발견해서 멈추기보다 전송 전에 충돌 가능성을 줄인다.

### 랜덤 백오프

여러 장치가 동시에 기다리고 있었다면 채널이 비는 순간 함께 전송할 수 있다. 이를 막기 위해 각 장치가 무작위 대기 시간을 선택한다.

```text
A의 대기 시간: 2
B의 대기 시간: 5

A가 먼저 전송
B는 A의 전송을 감지하고 카운트다운을 멈춤
```

### 링크 계층 ACK

무선에서는 프레임 손실이 자주 발생하므로 수신자가 정상 수신을 알리는 ACK를 보낸다.

```text
송신자 → DATA → 수신자
송신자 ← ACK  ← 수신자
```

ACK가 오지 않으면 송신자는 프레임이 손실되었다고 판단해 다시 보낸다.

### RTS와 CTS

숨은 터미널 문제를 완화하는 예약 방법이다.

#### RTS란?

**RTS(Request to Send)**는 송신자가 수신자에게 보내는 짧은 **전송 허가 요청 프레임**이다.

사람의 말로 바꾸면 다음과 같다.

> “제가 지금부터 데이터를 보내려고 합니다. 보내도 될까요?”

RTS에는 대략 다음 정보가 들어 있다.

- RTS를 받는 수신자의 MAC 주소
- RTS를 보내는 송신자의 MAC 주소
- DATA와 ACK까지 주고받는 데 필요한 예약 시간

RTS를 보내는 것 자체가 데이터를 전송해도 된다는 뜻은 아니다. 송신자는 수신자의 CTS가 올 때까지 기다려야 한다.

#### CTS란?

**CTS(Clear to Send)**는 수신자가 RTS에 응답하여 보내는 짧은 **전송 허가 프레임**이다.

사람의 말로 바꾸면 다음과 같다.

> “지금 보내도 됩니다. 주변 장치들은 그동안 기다려주세요.”

CTS는 RTS를 보낸 송신자를 수신자로 지정해 전송한다. 하지만 Wi-Fi 신호는 공기 중으로 퍼지므로 수신자 주변의 다른 장치들도 CTS를 들을 수 있다.

CTS를 들은 주변 장치는 그 안에 표시된 예약 시간 동안 자신이 데이터를 보내지 않고 기다린다.

#### NAV란?

CTS를 들은 주변 장치는 예약 시간을 **NAV(Network Allocation Vector)**라는 타이머에 기록한다.

```text
CTS에 적힌 남은 예약 시간: 3

C의 NAV: 3 → 2 → 1 → 0
                        ↓
                 다시 전송 경쟁 가능
```

NAV가 0보다 큰 동안에는 실제 채널이 조용하게 들리더라도 다른 장치가 사용하기로 예약된 것으로 판단한다. 이를 **가상 채널 감지**라고 한다.

#### 전체 동작 과정

```text
송신자 A              수신자 B              주변 장치 C
   │                     │                      │
   ├──── RTS ───────────→│                      │
   │  “보내도 될까요?”   │                      │
   │                     │                      │
   │←──── CTS ───────────┤ ── C도 CTS를 들음 ─→│
   │  “보내세요.”        │                      │ NAV 설정
   │                     │                      │ 전송 대기
   ├──── DATA ──────────→│                      │
   │                     │                      │
   │←──── ACK ───────────┤                      │
```

1. 송신자 A가 RTS로 전송 허가를 요청한다.
2. 수신자 B가 CTS로 전송을 허가한다.
3. 주변 장치 C는 CTS를 듣고 NAV 타이머를 설정한 뒤 기다린다.
4. A가 DATA를 전송한다.
5. B가 정상적으로 받았다면 ACK를 보낸다.

RTS와 CTS는 짧기 때문에 충돌해도 낭비가 작다. 하지만 항상 사용하면 제어 메시지 때문에 느려질 수 있어 보통 큰 프레임에 선택적으로 사용한다.

> RTS는 “보내도 될까요?”라는 요청이고, CTS는 “보내세요. 주변 장치는 기다리세요.”라는 허가다.

## 7.3.3 IEEE 802.11 프레임

Wi-Fi 프레임은 무선 통신에 필요한 정보를 담는 상자다.

- **페이로드:** IP 데이터그램이나 ARP 패킷
- **CRC:** 전송 중 오류 검사
- **순서 번호:** 새 프레임과 재전송 프레임 구분
- **Duration:** 채널을 얼마나 사용할지 표시
- **Frame Control:** DATA, ACK, RTS, CTS 등의 종류 표시
- **주소 필드:** 송신자, 수신자, AP, 유선망 쪽 장치 구분

### 주소가 여러 개인 이유

이더넷에서는 보통 출발지와 목적지 MAC 주소면 충분하다. Wi-Fi에서는 AP가 중간에 있기 때문에 주소가 더 필요하다.

```text
노트북 → AP → 라우터
```

AP는 Wi-Fi 프레임과 이더넷 프레임 사이를 변환하는 다리 역할을 한다.

### 순서 번호

ACK가 손실되면 송신자는 같은 프레임을 다시 보낼 수 있다. 수신자는 순서 번호를 보고 중복 프레임인지 판단한다.

## 7.3.4 같은 IP 서브넷 안에서의 이동

### 서브넷이란?

**서브넷(subnet)**은 하나의 큰 IP 네트워크를 작게 나눈 네트워크 구역이다.

아파트 단지로 비유하면 다음과 같다.

- IP 네트워크: 하나의 큰 도시
- 서브넷: 도시 안의 아파트 단지
- IP 주소: 각 세대의 주소
- 라우터: 다른 단지로 나가는 정문

같은 아파트 단지 안의 주민끼리는 단지 내부 길로 만날 수 있다. 다른 단지의 주민을 만나려면 정문을 통해 밖으로 나가야 한다.

네트워크도 비슷하다.

```text
같은 서브넷의 장치끼리
컴퓨터 A ─── 스위치·AP ─── 컴퓨터 B

다른 서브넷으로 통신
컴퓨터 A ─── 라우터 ─── 다른 서브넷의 서버
```

> 같은 서브넷의 장치는 라우터를 거치지 않고 직접 통신할 수 있고, 다른 서브넷으로 보낼 때는 일반적으로 기본 게이트웨이인 라우터를 거친다.

### 같은 서브넷인지 어떻게 알까?

장치는 자신의 **IP 주소와 서브넷 마스크**를 이용해 어느 서브넷에 속하는지 판단한다.

예를 들어 다음 네트워크를 생각해보자.

```text
서브넷: 192.168.1.0/24
```

`/24`는 IP 주소 앞의 24비트가 네트워크 구역을 나타낸다는 뜻이다. 이 예에서는 앞의 세 숫자 `192.168.1`이 같은 장치들이 일반적으로 같은 서브넷에 속한다.

```text
192.168.1.10 ┐
192.168.1.20 ├─ 같은 192.168.1.0/24 서브넷
192.168.1.99 ┘

192.168.2.10 ─ 다른 192.168.2.0/24 서브넷
```

| 장치 | IP 주소 | A와의 관계 |
|---|---|---|
| A | 192.168.1.10/24 | 기준 장치 |
| B | 192.168.1.20/24 | 같은 서브넷 |
| C | 192.168.2.20/24 | 다른 서브넷 |

이 예에서 A가 B에게 보낼 때는 ARP로 B의 MAC 주소를 알아내 직접 프레임을 보낸다. A가 C에게 보낼 때는 C가 아니라 **기본 게이트웨이의 MAC 주소**를 알아내 프레임을 먼저 라우터로 보낸다.

```text
A → B
IP 목적지:  B의 IP
MAC 목적지: B의 MAC

A → C
IP 목적지:  C의 IP
MAC 목적지: 기본 게이트웨이의 MAC
```

### 서브넷과 Wi-Fi 이름은 같은 개념일까?

아니다. SSID는 사용자가 보는 Wi-Fi 이름이고, 서브넷은 IP 주소로 구분되는 논리적인 네트워크 구역이다.

- 여러 AP가 같은 SSID와 같은 서브넷을 제공할 수 있다.
- SSID가 같더라도 설계에 따라 서로 다른 서브넷으로 연결될 수 있다.
- SSID가 달라도 같은 서브넷에 연결되도록 구성할 수도 있다.

따라서 Wi-Fi 이름만 보고 같은 서브넷인지 확정할 수는 없다.

### 같은 서브넷에서 AP만 바뀌는 경우

```text
AP 1 ─┐
      ├─ 같은 스위치·같은 서브넷 ─ 라우터
AP 2 ─┘
```

노트북이 AP 1에서 AP 2로 이동해도 같은 서브넷에 남아 있다면 기존 IP 주소를 유지할 수 있다. 최종 IP 주소가 그대로이므로 진행 중인 TCP 연결도 유지하기 쉽다.

### 다른 서브넷으로 이동하는 경우

```text
AP 1 → 192.168.1.0/24
AP 2 → 192.168.2.0/24
```

AP 2로 이동하면서 다른 서브넷에 들어가면 DHCP를 통해 새로운 IP 주소를 받을 수 있다. 기존 TCP 연결은 출발지 IP 주소를 포함해 연결을 구분하므로 IP가 바뀌면 보통 그대로 유지하기 어렵다.

앱 개발자는 이런 네트워크 변경을 정상 상황으로 보고 재연결과 요청 복구를 준비해야 한다.

학교에 여러 AP가 있고 모두 같은 IP 서브넷에 연결되어 있다고 하자.

```text
AP 1 ─┐
      ├─ 스위치 ─ 라우터
AP 2 ─┘
```

노트북이 AP 1 영역에서 AP 2 영역으로 이동해도 같은 서브넷 안이라면 IP 주소를 유지할 수 있다. 따라서 진행 중인 TCP 연결도 유지하기 쉽다.

스위치는 노트북이 이제 AP 2 쪽에 있다는 사실을 새로 학습해 포워딩 테이블을 갱신한다.

---

## 7.3.5 Wi-Fi의 고급 기능

### 전송률 적응

AP와 가까워 신호가 좋으면 빠른 방식을 사용하고, 멀어져 신호가 약해지면 느리지만 오류에 강한 방식으로 바꾼다.

```text
AP와 가까움 → 빠른 속도
AP와 멂    → 느리지만 안정적인 속도
```

### 전력 제어

무선 회로를 계속 켜두면 배터리가 빨리 소모된다. 장치는 AP에게 잠들겠다고 알리고 무선 회로를 잠시 끈다.

AP는 그동안 도착한 프레임을 보관한다. 장치는 비컨 시간에 맞춰 잠깐 깨어나 자신에게 온 데이터가 있는지 확인한다.

## 7.3.6 블루투스 PAN

블루투스는 가까운 거리에서 저전력으로 장치를 연결하는 개인 영역 네트워크다.

- 이어폰
- 키보드와 마우스
- 스마트워치
- 자동차 오디오

### 주파수 도약

블루투스는 2.4GHz 대역에서 통신하면서 사용할 주파수를 계속 바꾼다.

```text
시간 1: 채널 7
시간 2: 채널 42
시간 3: 채널 18
```

특정 채널에 간섭이 있어도 다음 순간에는 다른 채널을 사용하므로 간섭의 영향을 줄일 수 있다. 이를 FHSS라고 한다.

### 피코넷

블루투스 장치들이 즉석에서 만드는 작은 네트워크다. 하나의 중앙 제어 장치가 시간과 주파수 도약 순서를 관리하고 다른 장치에 전송 기회를 준다.

### 이웃 탐색

AP가 없기 때문에 주변 장치를 직접 찾아야 한다.

1. 중앙 장치가 여러 주파수로 조회 메시지를 보낸다.
2. 주변 장치가 무작위 시간 후 응답한다.
3. 중앙 장치가 가입할 장치를 초대한다.
4. 시간과 주파수 정보를 맞춘 후 통신을 시작한다.

# 7.4 셀룰러 네트워크: 4G와 5G

셀룰러 네트워크는 전체 지역을 여러 개의 **셀**로 나눈다. 각 셀에는 해당 지역의 장치를 관리하는 기지국이 있다.

```text
[셀 A: 기지국 A] [셀 B: 기지국 B] [셀 C: 기지국 C]
```

---

## 7.4.1 4G LTE의 구조

### 이동 장치·UE

스마트폰, 태블릿, IoT 장치처럼 셀룰러 네트워크에 접속하는 장치다.

SIM에는 가입자를 구별하는 IMSI와 인증 정보가 저장된다.

- **IP 주소:** 데이터 전달에 사용
- **IMSI:** 통신사가 가입자를 식별하는 데 사용

### 기지국

이동 장치와 직접 무선 통신하며 다음 작업을 담당한다.

- 무선 자원 할당
- 장치 접속 관리
- 이동성 처리
- 주변 기지국과 간섭 조정

### HSS

가입자 정보를 저장하는 통신사의 회원 데이터베이스다.

- 가입자와 인증 정보
- 이용할 수 있는 서비스
- 암호화에 필요한 정보
- 사용자의 현재 위치와 관련된 정보

### MME

데이터를 직접 운반하기보다 네트워크를 지휘하는 제어 담당자다.

- 사용자 인증
- 장치 위치 관리
- 데이터가 지나갈 터널 설정
- 수면 중인 장치 페이징

### S-GW와 P-GW

스마트폰의 데이터를 인터넷까지 전달하는 게이트웨이다.

```text
스마트폰
  ↓
기지국
  ↓
S-GW
  ↓
P-GW
  ↓
인터넷
```

P-GW는 외부 인터넷으로 나가는 출입구이며 IP 주소 관리와 NAT 기능도 수행할 수 있다.

### 제어 평면과 데이터 평면

- **제어 평면:** 인증, 경로 설정, 이동성 관리 등의 지시
- **데이터 평면:** 영상, 메시지, 웹 데이터 같은 실제 사용자 데이터

제어 평면은 교통 관제실이고, 데이터 평면은 자동차가 실제로 다니는 도로와 같다.

### 2G에서 4G까지의 변화

- **2G:** 음성 통화 중심
- **3G:** 음성과 패킷 데이터망을 함께 지원
- **4G:** 음성까지 포함해 IP 중심의 all-IP 구조

---

## 7.4.2 LTE 프로토콜 스택

LTE의 링크 계층은 크게 세 부분으로 나뉜다.

### PDCP

- IP 헤더 압축
- 데이터 암호화와 복호화

무선 구간에서 불필요한 데이터 크기를 줄이고 보안을 담당한다.

### RLC

- 큰 데이터를 작은 조각으로 나눈다.
- 수신 측에서 다시 조립한다.
- ACK·NAK을 이용해 필요한 데이터를 재전송한다.

### MAC

- 누가 어느 시간과 주파수를 사용할지 스케줄링한다.
- 오류 검출과 정정을 수행한다.

### LTE의 터널

LTE 코어에서는 사용자별 데이터 경로를 터널처럼 만든다. 터널에는 TEID라는 번호가 붙어 어느 사용자의 데이터인지 구별한다.

---

## 7.4.3 LTE 무선 접속 네트워크

LTE는 시간과 주파수를 작은 칸으로 나누어 사용자들에게 배정한다.

```text
             시간 →
주파수 1 | A | A | B | C |
주파수 2 | B | C | C | A |
주파수 3 | A | B | B | C |
```

기지국의 스케줄러는 신호 상태, 요청한 데이터량, 서비스 우선순위, 셀의 혼잡도 등을 고려해 자원을 나눈다.

---

## 7.4.4 LTE 접속과 전력 관리

### 네트워크 접속

1. 주변 기지국의 동기화 신호를 찾는다.
2. 연결할 기지국을 선택한다.
3. SIM과 HSS 정보를 이용해 네트워크와 장치가 서로 인증한다.
4. 기지국부터 게이트웨이까지 터널을 설정한다.
5. 인터넷 데이터 송수신을 시작한다.

### 불연속 수신 상태

얕은 잠과 같다. 장치가 짧게 잠들었다가 약속한 시각에 주기적으로 깨어나 자신에게 온 데이터가 있는지 확인한다.

### 유휴 상태

깊은 잠과 같다. 장치가 다른 셀로 이동해도 이전 기지국에 바로 알리지 않을 수 있다.

데이터가 도착하면 네트워크가 여러 기지국에 페이징 메시지를 방송해 장치를 찾는다.

---

## 7.4.5 글로벌 셀룰러 네트워크

각 통신사의 네트워크도 인터넷이나 통신사 전용 상호연결망을 통해 서로 연결된다.

```text
내가 가입한 통신사
        ↓
해외의 다른 통신사
        ↓
글로벌 인터넷과 서비스
```

덕분에 해외에서도 다른 통신사의 기지국을 이용해 로밍할 수 있다.

---

## 7.4.6 5G

5G는 크게 세 종류의 서비스를 목표로 설계되었다.

### eMBB

빠른 모바일 인터넷을 위한 서비스다.

- 고화질 영상
- 대용량 다운로드
- AR·VR

### URLLC

매우 짧은 지연과 높은 신뢰성이 필요한 서비스다.

- 공장 자동화
- 원격 제어
- 자율주행 관련 통신

### mMTC

수많은 저전력 IoT 장치를 연결하기 위한 서비스다.

- 환경 센서
- 스마트 계량기
- 농업 센서

### 밀리미터파

높은 주파수를 이용해 많은 데이터를 빠르게 전송할 수 있지만 도달 거리가 짧고 벽, 나무, 비 같은 장애물에 약하다.

그래서 작은 기지국을 촘촘하게 설치하고 다음 기술을 활용한다.

- **빔포밍:** 신호를 사용자 방향으로 집중
- **MIMO:** 여러 안테나를 사용해 동시에 통신

### 5G 코어

5G 코어는 기능을 소프트웨어 형태로 나누고 제어 평면과 사용자 평면을 분리한다.

- **UPF:** 실제 사용자 패킷 전달
- **AMF:** 장치 접속과 이동성 관리
- **SMF:** 데이터 세션과 IP 주소 관리

4G의 MME가 맡던 일을 5G에서는 AMF와 SMF 등이 더 세분화해 처리한다고 이해하면 된다.

# 7.5 이동성 관리의 원칙

네트워크에서 이동성이란 단순히 사람이 움직인다는 뜻이 아니다.

> 장치가 통신을 계속하면서 네트워크 접속 지점을 바꾸는 것이 중요한 이동성이다.

## 7.5.1 이동성의 단계

1. **전원을 끄고 다른 장소로 이동:** 유지할 네트워크 연결이 없다.
2. **같은 AP 범위에서 이동:** 접속 지점이 바뀌지 않는다.
3. **연결을 유지하며 다른 AP·기지국으로 이동:** 핸드오버가 필요하다.
4. **연결을 유지하며 다른 통신사로 이동:** 통신사 사이의 협력까지 필요하다.

뒤로 갈수록 이동성을 처리하기 어려워진다.

---

## 7.5.2 홈 네트워크와 방문 네트워크

- **홈 네트워크:** 내가 가입한 통신사의 네트워크
- **방문 네트워크:** 로밍 중에 빌려 쓰는 다른 통신사의 네트워크

```text
내 통신사 = 홈 네트워크
현재 빌려 쓰는 통신사 = 방문 네트워크
```

방문 네트워크는 홈 네트워크에 정보를 요청해 사용자를 인증한다. 홈 네트워크는 사용자의 현재 위치를 기록한다.

---

## 7.5.3 이동 장치로 데이터를 보내는 방법

### 기존 라우팅만 사용하는 방법

모든 라우터에게 “이 사용자가 지금 이 네트워크에 있다”고 알릴 수는 있다. 하지만 수십억 장치가 이동할 때마다 전 세계 라우터의 정보를 바꾸는 것은 현실적으로 어렵다.

따라서 홈 네트워크가 장치의 현재 위치를 관리하는 방식을 사용한다.

### 간접 라우팅

송신자는 장치의 현재 위치를 몰라도 된다. 데이터를 먼저 장치의 홈 네트워크로 보낸다.

```text
송신자
  ↓
이동 장치의 홈 네트워크
  ↓ 터널
현재 방문 네트워크
  ↓
이동 장치
```

홈 네트워크는 HSS에서 장치의 위치를 확인하고 방문 네트워크로 데이터를 터널링한다.

- **장점:** 송신자가 이동성을 신경 쓰지 않아도 된다.
- **단점:** 가까운 곳끼리 통신해도 홈 네트워크를 돌아갈 수 있다.

이처럼 불필요하게 먼 경로를 거치는 문제를 **삼각 라우팅 문제**라고 한다.

### 직접 라우팅

송신자가 홈 네트워크에 장치의 위치를 문의한 뒤 방문 네트워크로 직접 보낸다.

```text
송신자 ─────────→ 방문 네트워크 → 이동 장치
       위치는 HSS에 문의
```

경로는 짧지만 장치가 다시 이동하면 송신자에게 새 위치를 알려줘야 하므로 관리가 더 복잡하다.

# 7.6 실제 이동성 관리

## 7.6.1 4G·5G의 핸드오버

자동차에서 영상을 보고 있을 때 차량이 이동하면 스마트폰은 한 셀에서 다른 셀로 넘어간다.

1. 스마트폰이 주변 기지국들의 신호를 측정한다.
2. 현재 기지국이 새로운 목적지 기지국을 선택한다.
3. 목적지 기지국에 핸드오버를 요청한다.
4. 목적지 기지국이 채널과 자원을 미리 준비한다.
5. 스마트폰이 새로운 기지국에 연결한다.
6. 이전 기지국이 남은 데이터를 새 기지국에 전달한다.
7. 코어 네트워크가 터널의 끝을 새 기지국으로 변경한다.
8. 이전 기지국이 사용하던 자원을 해제한다.

핵심은 스마트폰만 기지국을 바꾸는 것이 아니라 네트워크 내부의 데이터 터널도 함께 바뀐다는 것이다.

---

## 7.6.2 이동 IP

일반 인터넷에서도 장치가 네트워크를 옮기면서 기존 주소와 연결을 유지할 수 있도록 이동 IP가 제안되었다.

### 에이전트 발견

이동 장치가 현재 방문 중인 네트워크에서 이동성 지원 장치를 찾는다.

### 홈 에이전트 등록

방문 네트워크에서 사용할 임시 주소인 **COA(Care-of Address)**를 홈 에이전트에 등록한다.

COA는 지금 머무는 숙소의 주소와 비슷하다.

### 간접 라우팅

홈 에이전트가 이동 장치의 영구 주소로 온 데이터를 받아 COA로 터널링한다.

```text
영구 주소 → 홈 에이전트 → COA → 이동 장치
```

셀룰러 네트워크의 홈 네트워크, 방문 네트워크, 터널링과 비슷한 구조다.

# 7.7 상위 계층 프로토콜에 미치는 영향

## TCP에 미치는 영향

TCP는 패킷이 손실되면 보통 네트워크가 혼잡하다고 판단한다. 그러나 무선 네트워크의 손실 원인은 다양하다.

- 실제 네트워크 혼잡
- 약한 신호
- 간섭과 비트 오류
- 핸드오버 중의 지연
- 일시적인 연결 끊김

TCP는 손실 이유를 알지 못하므로 무선 오류도 혼잡으로 오해하고 전송 속도를 낮출 수 있다.

```text
TCP: “패킷이 없어졌네? 네트워크가 혼잡한가 보다.”
실제 상황: “혼잡이 아니라 무선 신호가 잠깐 약했던 것”
```

### 개선 방법

- **지역 복구:** 무선 링크에서 직접 재전송
- **무선 링크 인지:** 혼잡 손실과 무선 손실을 구별
- **연결 분리:** 유선 구간과 무선 구간의 연결을 따로 관리

## 애플리케이션 계층에 미치는 영향

무선 대역폭은 여러 사용자가 공유하고 신호 상태도 계속 달라진다. 영상 앱 등이 네트워크 상태에 따라 화질을 조절하는 이유다.

반대로 무선과 이동성 덕분에 새로운 애플리케이션도 가능해졌다.

- 지도와 길 안내
- 위치 기반 추천
- 차량 호출
- 실시간 배달 추적
- 스마트워치와 건강 모니터링
- 위치·상황 인식 서비스

# 학습 내용 요약

1. 무선 네트워크는 무선 호스트, 무선 링크, 기지국, 네트워크 인프라로 구성된다.
2. 홉은 데이터가 한 장치에서 다음 장치로 한 번 이동하는 것이다.
3. 무선 신호는 경로 손실, 간섭, 다중 경로 전파, 페이딩의 영향을 받는다.
4. SNR이 높을수록 일반적으로 오류율인 BER은 낮아진다.
5. Wi-Fi는 충돌 검출 대신 CSMA/CA로 충돌을 피하려고 한다.
6. Wi-Fi는 ACK와 재전송을 사용하며 숨은 터미널 문제는 RTS·CTS로 완화할 수 있다.
7. 블루투스는 짧은 거리에서 저전력으로 동작하며 주파수를 계속 바꾼다.
8. 4G·5G는 지역을 셀로 나누고 각 셀의 기지국이 이동 장치를 관리한다.
9. 제어 평면은 인증과 경로를 관리하고 데이터 평면은 실제 사용자 데이터를 운반한다.
10. 이동 중 기지국이 바뀌는 과정을 핸드오버라고 한다.
11. 간접 라우팅은 관리가 쉽지만 홈 네트워크를 돌아가는 삼각 라우팅 문제가 있다.
12. TCP는 무선 오류를 혼잡으로 오해해 불필요하게 속도를 낮출 수 있다.

> 7장은 불안정한 전파를 여러 장치가 나누어 사용하면서도, 사용자가 이동할 때 인터넷 연결을 최대한 끊기지 않게 유지하는 방법을 배우는 장이다.

# 앱 개발자 관점에서 보는 7장

## Wi-Fi와 4G·5G의 차이

가장 큰 차이는 **누가 운영하고 얼마나 넓은 지역을 책임지는가**다.

> Wi-Fi는 집이나 학교 안의 작은 무선 네트워크이고, 4G·5G는 통신사가 도시와 나라 전체에 설치한 이동통신 네트워크다.

| 구분 | Wi-Fi | 4G·5G |
|---|---|---|
| 관리 주체 | 집, 회사, 카페의 공유기 관리자 | 이동통신사 |
| 연결 장치 | AP·공유기 | 셀룰러 기지국 |
| 통신 범위 | 주로 집이나 건물 내부 | 도시와 전국 |
| 사용자 인증 | Wi-Fi 비밀번호 등 | SIM·eSIM과 가입자 정보 |
| 이동성 | AP에서 멀어지면 쉽게 끊길 수 있음 | 이동 중 기지국이 바뀌어도 연결 유지 |
| 채널 사용 | 장치들이 경쟁해 전송 | 기지국이 시간과 주파수를 배정 |
| 주파수 | 주로 비면허 대역 | 통신사가 확보한 면허 대역 중심 |
| 비용 | 인터넷 회선과 공유기 비용 | 통신사 데이터 요금제 |
| 주요 목적 | 한정된 장소에서 빠른 인터넷 | 넓은 지역에서 끊김 없는 통신 |

### Wi-Fi의 통신 방식

```text
스마트폰 → Wi-Fi 공유기 → 인터넷
```

여러 장치가 같은 채널을 함께 사용한다. 각 장치는 다른 장치가 전송 중인지 확인하고 채널이 비어 있으면 데이터를 보낸다. 이것이 CSMA/CA다.

```text
“다른 장치가 전송 중인가?”
   ├─ 예 → 기다림
   └─ 아니요 → 전송
```

### 4G·5G의 통신 방식

```text
스마트폰
  ↓
기지국
  ↓
통신사 코어 네트워크
  ↓
인터넷
```

기지국이 사용자마다 사용할 시간과 주파수를 배정한다. 사용자가 이동하면 현재 기지국이 다음 기지국으로 연결을 넘겨주는 핸드오버도 수행한다.

### 꼭 알아둘 점

5G가 항상 Wi-Fi보다 빠른 것은 아니다. 실제 속도는 다음 조건에 따라 달라진다.

- 기지국·공유기와의 거리
- 신호를 막는 장애물
- 같은 네트워크를 사용하는 사람 수
- 사용하는 주파수
- 인터넷 회선과 서버 상태

---

## 앱 개발자에게 중요한 핵심

무선 통신의 세부 계산보다 다음 사실이 중요하다.

> 사용자는 Wi-Fi와 4G·5G 사이를 계속 이동하며, 그 과정에서 속도, 지연 시간, IP 주소, 연결 상태가 언제든 바뀔 수 있다.

## 1. 네트워크가 사용 중에 바뀔 수 있다

```text
집 Wi-Fi
   ↓
엘리베이터에서 Wi-Fi 끊김
   ↓
4G·5G로 전환
```

네트워크가 바뀌면 기존 TCP나 WebSocket 연결이 끊길 수 있다.

앱은 다음 상황을 처리해야 한다.

- 연결 끊김 감지
- 안전한 재연결
- 진행 중이던 요청 재시도
- 중복 요청 방지
- 화면 상태와 임시 데이터 유지

## 2. 네트워크 연결과 인터넷 연결은 다르다

Wi-Fi에 연결되어 있어도 인터넷을 사용할 수 없는 상황이 있다.

```text
스마트폰 ↔ 공유기 연결 성공
공유기 ↔ 인터넷 연결 실패
```

따라서 단순히 Wi-Fi 연결 여부만 확인해서는 안 된다. 실제 인터넷 사용 가능 여부를 함께 고려해야 한다.

## 3. 속도와 지연 시간은 계속 변한다

5G 표시가 있어도 기지국이 혼잡하거나 신호가 약하면 느릴 수 있다. Wi-Fi도 공유기와의 거리나 동시 사용자 수에 따라 성능이 달라진다.

앱은 네트워크 상태에 맞게 동작을 조절할 수 있어야 한다.

- 이미지 크기와 품질 조정
- 동영상 화질 자동 변경
- 페이지 단위 데이터 요청
- 재개 가능한 파일 업로드와 다운로드
- 너무 짧지 않은 타임아웃 설정
- 필요한 데이터의 캐싱

## 4. 패킷 손실은 정상적으로 발생할 수 있다

터널, 엘리베이터, 지하철, 핸드오버 과정에서는 일시적인 패킷 손실이 생길 수 있다.

```text
요청 실패
├─ 서버 오류
├─ 네트워크 없음
├─ 타임아웃
├─ DNS 실패
└─ 이동 중 네트워크 변경
```

따라서 요청 실패를 모두 서버 장애로 처리하면 안 된다. 실패 원인에 따라 사용자 메시지와 재시도 방법을 다르게 정해야 한다.

## 5. 재시도는 중복 처리를 만들 수 있다

결제 요청의 응답을 받기 전에 네트워크가 끊기는 상황을 생각해보자.

```text
앱 → 결제 요청 → 서버에서 결제 성공
             ✕ 응답은 앱에 도착하지 않음

앱 → 같은 결제 요청을 다시 전송
```

서버에서는 첫 요청이 이미 처리되었을 수 있다. 앱이 무조건 다시 요청하면 이중 결제나 중복 주문이 생길 수 있다.

따라서 중요한 쓰기 요청은 다음처럼 설계해야 한다.

- 멱등성 키 사용
- 서버에서 중복 요청 검사
- 요청 결과 조회 기능 제공
- 읽기 요청과 쓰기 요청의 재시도 정책 분리

## 6. 모바일 데이터는 비용과 배터리를 사용한다

대용량 동기화나 영상 다운로드는 사용자의 데이터 요금과 배터리를 많이 소비할 수 있다.

- 모바일 데이터 사용 여부 확인
- Wi-Fi에서만 다운로드하는 옵션 제공
- 백그라운드 작업 제한 고려
- 여러 요청을 묶어서 처리
- 큰 파일은 중단된 위치부터 재개
- 불필요한 폴링 줄이기

## 7. 오프라인도 정상 상태로 다룬다

모바일 앱에서는 네트워크가 없는 상태가 예외적인 버그가 아니다. 지하철, 엘리베이터, 해외 로밍, 비행기 모드 등에서 언제든 발생할 수 있다.

가능하다면 다음 기능을 고려한다.

- 마지막으로 받은 데이터 표시
- 사용자 입력의 임시 저장
- 오프라인 작업 큐
- 네트워크 복구 후 동기화
- 동기화 충돌 처리

## 앱 개발자용 핵심 문장

> 네트워크는 항상 연결되어 있는 빠르고 고정된 통로가 아니라, 이동 중 끊기고 바뀌고 느려질 수 있는 외부 환경이다.

따라서 좋은 네트워크 앱은 정상 요청만 구현하는 앱이 아니다. **끊김, 재연결, 중복, 지연, 오프라인까지 정상적인 사용자 흐름으로 취급하는 앱**이다.
