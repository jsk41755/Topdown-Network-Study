# 링크 계층 복습 질문과 답변

> 질문을 보고 먼저 자신의 말로 설명한 다음 **정답 보기**를 펼쳐 확인한다.  
> 세부 수치 암기보다 각 기술이 **왜 필요하고 어떻게 연결되는지** 이해하는 데 초점을 둔다.

---

## 1. 링크 계층의 기본 개념

### Q1. 링크 계층은 어떤 범위의 데이터 전달을 담당하는가?

<details>
<summary>정답 보기</summary>

전체 출발지에서 최종 목적지까지가 아니라 통신 경로에서 **서로 인접한 두 노드 사이**의 전달을 담당한다. 호스트, 라우터, 스위치, AP 등이 노드이며, 인접한 노드를 연결하는 통신 채널이 링크다.

</details>

### Q2. 프레임화란 무엇이며, 데이터그램이 여러 링크를 지날 때 프레임은 어떻게 되는가?

<details>
<summary>정답 보기</summary>

프레임화는 네트워크 계층의 IP 데이터그램을 링크 계층 프레임 안에 넣는 것이다. 데이터그램은 최종 목적지까지 전달되지만, 프레임은 현재 링크에 맞게 각 구간에서 새로 만들어질 수 있다.

</details>

### Q3. 링크 계층이 제공하는 주요 서비스를 설명해 보자.

<details>
<summary>정답 보기</summary>

- **프레임화**: 데이터그램을 프레임으로 캡슐화한다.
- **링크 접속**: MAC 프로토콜로 누가 언제 링크를 사용할지 정한다.
- **신뢰적 전달**: 필요한 링크에서 확인 응답과 재전송을 수행한다.
- **오류 검출·정정**: 전송 중 비트가 바뀌었는지 확인하고 가능한 경우 고친다.

</details>

### Q4. 링크 계층은 호스트의 어디에 구현되는가?

<details>
<summary>정답 보기</summary>

주로 NIC, 즉 네트워크 어댑터에 구현된다. 프레임 처리 같은 기능은 컨트롤러 하드웨어가 담당하고, 주소 정보 조립과 오류 처리 등의 일부 기능은 CPU에서 실행되는 소프트웨어가 담당한다. 따라서 링크 계층은 **하드웨어와 소프트웨어의 조합**이다.

</details>

## 2. 오류 검출과 정정

### Q5. 패리티 검사의 원리와 한계는 무엇인가?

<details>
<summary>정답 보기</summary>

데이터에 있는 `1`의 전체 개수를 짝수 또는 홀수로 맞추기 위해 패리티 비트를 추가한다. 단일 패리티는 홀수 개의 비트 오류는 찾을 수 있지만 짝수 개의 비트 오류를 놓칠 수 있다. 2차원 패리티는 행과 열을 함께 검사해 한 비트 오류의 위치를 찾아 고칠 수도 있다.

</details>

### Q6. 체크섬과 CRC는 어떻게 다르며 각각 어디에 주로 사용되는가?

<details>
<summary>정답 보기</summary>

체크섬은 데이터를 여러 정수처럼 보고 더한 결과로 오류를 검사한다. 계산이 단순해 TCP와 UDP에서 사용된다. CRC는 생성자와 모듈로 2 나눗셈을 이용하며 계산은 더 복잡하지만 오류 검출 능력이 강해 이더넷 같은 링크 계층에서 널리 사용된다.

</details>

### Q7. CRC는 송신자와 수신자에서 어떻게 동작하는가?

<details>
<summary>정답 보기</summary>

송신자와 수신자는 생성자 `G`를 미리 합의한다. 송신자는 데이터 뒤에 나머지 `R`을 붙여 전체 비트열이 `G`로 나누어떨어지도록 만든다. 수신자는 받은 비트열을 `G`로 나누어 나머지가 0이 아니면 오류로 판단한다. 이때 모듈로 2 연산은 비트별 XOR과 같다.

</details>

## 3. 공유 채널과 다중 접속

### Q8. 점대점 링크와 브로드캐스트 링크의 차이는 무엇인가?

<details>
<summary>정답 보기</summary>

점대점 링크는 한 송신자와 한 수신자가 링크 양 끝에 연결된다. 브로드캐스트 링크는 여러 노드가 하나의 채널을 공유하며, 한 노드가 전송한 프레임을 여러 노드가 받을 수 있다.

</details>

### Q9. 다중 접속 문제는 왜 발생하는가?

<details>
<summary>정답 보기</summary>

공유 채널에서 둘 이상의 노드가 동시에 프레임을 전송하면 신호가 겹쳐 충돌한다. 충돌한 프레임은 제대로 해석할 수 없으므로 채널 대역폭이 낭비된다. 다중 접속 프로토콜은 노드들의 전송 시점을 조정한다.

</details>

### Q10. TDM, FDM, CDMA는 채널을 각각 어떻게 나누는가?

<details>
<summary>정답 보기</summary>

- **TDM**: 사용 시간을 슬롯으로 나눈다.
- **FDM**: 주파수 대역을 나눈다.
- **CDMA**: 노드마다 서로 다른 코드를 부여한다.

TDM과 FDM은 충돌이 없고 공정하지만 사용하지 않는 노드에 배정된 자원이 낭비될 수 있다. CDMA는 코드를 적절히 선택하면 여러 노드가 동시에 전송할 수 있다.

</details>

### Q11. 슬롯 ALOHA와 순수 ALOHA는 어떻게 다른가?

<details>
<summary>정답 보기</summary>

슬롯 ALOHA는 시간을 슬롯으로 나누고 슬롯 시작점에서만 전송한다. 순수 ALOHA는 프레임이 생기면 즉시 전송한다. 순수 ALOHA는 동기화가 필요 없지만 충돌 범위가 넓어 최대 효율이 약 18%이며, 슬롯 ALOHA의 약 37%보다 낮다.

</details>

### Q12. CSMA가 먼저 채널을 확인하고도 충돌할 수 있는 이유는 무엇인가?

<details>
<summary>정답 보기</summary>

신호가 다른 노드까지 전달되는 데 시간이 걸리는 **전파 지연** 때문이다. 멀리 떨어진 두 노드가 상대방의 신호를 아직 받지 못한 상태에서 모두 채널이 비었다고 판단하고 동시에 전송할 수 있다.

</details>

### Q13. CSMA/CD와 이진 지수적 백오프는 어떻게 동작하는가?

<details>
<summary>정답 보기</summary>

CSMA/CD는 전송 전에 채널을 확인하고, 전송 중 충돌을 감지하면 즉시 전송을 중단한다. 이후 무작위 시간 동안 기다렸다가 다시 시도한다. 충돌이 반복될수록 대기 시간을 선택하는 범위를 지수적으로 넓히는 방법이 이진 지수적 백오프다.

</details>

### Q14. 폴링과 토큰 전달은 전송 순서를 어떻게 정하며 어떤 약점이 있는가?

<details>
<summary>정답 보기</summary>

폴링은 마스터 노드가 각 노드에 차례로 전송 기회를 준다. 마스터가 고장 나면 전체 통신이 멈출 수 있다. 토큰 전달은 특별한 토큰 프레임을 정해진 순서로 넘기며 토큰을 가진 노드가 전송한다. 토큰이 사라지거나 한 노드가 토큰을 놓지 않으면 복구 절차가 필요하다.

</details>

## 4. MAC 주소, ARP, 이더넷

### Q15. IP 주소와 MAC 주소는 각각 어떤 역할을 하는가?

<details>
<summary>정답 보기</summary>

IP 주소는 서로 다른 네트워크를 지나 **최종 목적지까지 경로를 찾는 데** 사용된다. MAC 주소는 현재 링크나 LAN에서 **다음 인터페이스로 프레임을 전달하는 데** 사용된다. MAC 주소는 호스트 자체가 아니라 네트워크 인터페이스에 속한다.

</details>

### Q16. ARP는 무엇을 해결하며 어떻게 동작하는가?

<details>
<summary>정답 보기</summary>

ARP는 같은 서브넷에서 IP 주소에 대응하는 MAC 주소를 찾는다. 송신자는 `FF:FF:FF:FF:FF:FF`를 목적지로 ARP 질의를 브로드캐스트한다. 해당 IP 주소를 가진 노드가 자신의 MAC 주소를 유니캐스트로 응답하고, 송신자는 결과를 ARP 테이블에 임시 저장한다.

</details>

### Q17. 다른 서브넷의 서버로 보낼 때 목적지 IP와 목적지 MAC은 누구의 주소인가?

<details>
<summary>정답 보기</summary>

목적지 IP는 **최종 서버의 IP 주소**이고, 현재 프레임의 목적지 MAC은 **기본 게이트웨이인 라우터 인터페이스의 MAC 주소**다. 라우터를 지날 때마다 프레임과 MAC 주소는 다음 링크에 맞게 바뀌지만 최종 목적지 IP 주소는 유지된다.

</details>

### Q18. 이더넷 프레임의 주요 필드와 역할을 설명해 보자.

<details>
<summary>정답 보기</summary>

- **프리앰블**: 프레임 시작을 알리고 송수신 클록을 맞춘다.
- **출발지·목적지 주소**: 송수신 인터페이스의 MAC 주소를 담는다.
- **타입**: 데이터 필드에 들어 있는 상위 프로토콜을 구분한다.
- **데이터**: 주로 IP 데이터그램을 운반한다.
- **CRC**: 전송 중 오류가 생겼는지 검사한다.

</details>

### Q19. 이더넷이 비연결형·비신뢰적 서비스라는 것은 무슨 뜻인가?

<details>
<summary>정답 보기</summary>

프레임을 보내기 전에 연결 설정이나 핸드셰이크를 하지 않고, 수신자가 프레임마다 ACK나 NAK를 보내지도 않는다는 뜻이다. CRC에서 오류가 발견되면 프레임을 버리며, 필요한 복구는 TCP 같은 상위 계층이 담당할 수 있다.

</details>

## 5. 스위치, 라우터, VLAN

### Q20. 스위치는 스위치 테이블을 어떻게 자가학습하는가?

<details>
<summary>정답 보기</summary>

수신한 프레임의 **출발지 MAC 주소**와 프레임이 들어온 포트를 함께 기록한다. 이후 해당 MAC 주소가 목적지인 프레임을 알맞은 포트로 보낼 수 있다. 오랫동안 사용되지 않은 정보는 에이징 시간이 지나면 삭제한다.

</details>

### Q21. 스위치가 목적지 MAC 주소를 모를 때와 알 때 각각 어떻게 동작하는가?

<details>
<summary>정답 보기</summary>

목적지를 모르면 프레임이 들어온 포트를 제외한 모든 포트로 플러딩한다. 목적지를 알면 해당 포트로만 포워딩한다. 목적지가 프레임이 들어온 포트 쪽에 있다면 다른 포트로 보낼 필요가 없어 필터링한다.

</details>

### Q22. 현대의 스위치 기반 이더넷에서 일반적으로 CSMA/CD가 필요 없는 이유는 무엇인가?

<details>
<summary>정답 보기</summary>

각 호스트가 스위치와 독립된 점대점 링크로 연결되고 일반적으로 전이중 통신을 사용해 충돌하지 않기 때문이다. CSMA/CD는 여러 장치가 통신 매체를 공유하던 버스나 허브 기반 이더넷에서 필요했다.

</details>

### Q23. 스위치와 라우터의 핵심 차이는 무엇인가?

<details>
<summary>정답 보기</summary>

스위치는 2계층 장치로 MAC 주소를 보고 주로 같은 LAN 안에서 프레임을 전달한다. 라우터는 3계층 장치로 IP 주소와 포워딩 테이블을 보고 서로 다른 네트워크 사이에서 데이터그램을 전달한다.

</details>

### Q24. VLAN은 무엇이며 왜 사용하는가?

<details>
<summary>정답 보기</summary>

VLAN은 하나의 물리적 스위치 네트워크를 여러 논리적 LAN으로 나누는 기술이다. 브로드캐스트 범위를 줄이고 그룹 사이의 트래픽을 격리하며, 물리적 케이블을 바꾸지 않고 사용자의 논리적 소속을 변경할 수 있다.

</details>

### Q25. 서로 다른 VLAN 사이의 통신과 스위치 사이의 VLAN 전달에는 무엇이 필요한가?

<details>
<summary>정답 보기</summary>

서로 다른 VLAN은 논리적으로 다른 LAN이므로 라우터나 3계층 스위치를 통한 라우팅이 필요하다. 여러 VLAN의 프레임을 스위치 사이의 한 링크로 전달할 때는 트렁크를 사용하며, 프레임이 어느 VLAN 소속인지 VLAN 태그로 표시한다.

</details>

## 6. MPLS와 데이터 센터

### Q26. MPLS의 핵심 아이디어와 장점은 무엇인가?

<details>
<summary>정답 보기</summary>

일부 패킷에 짧은 레이블을 붙여 MPLS 라우터가 목적지 IP 대신 레이블을 보고 전달하도록 하는 기술이다. 일반 IP 라우팅의 최소 비용 경로 외에 관리자가 원하는 경로를 사용할 수 있어 트래픽 엔지니어링에 유용하다.

</details>

### Q27. 데이터 센터의 주요 구성 요소와 역할을 설명해 보자.

<details>
<summary>정답 보기</summary>

서버는 랙에 적재되고 랙의 서버들은 TOR 스위치에 연결된다. 상위 스위치들이 여러 랙을 연결하고, 경계 라우터가 데이터 센터와 인터넷을 연결한다. 로드 밸런서는 외부 요청을 여러 서버에 분산한다.

</details>

### Q28. 데이터 센터에 여러 장비와 경로를 중복해서 두는 이유는 무엇인가?

<details>
<summary>정답 보기</summary>

장비나 링크 하나가 고장 나도 다른 경로로 서비스를 계속 제공해 가용성과 신뢰성을 높이기 위해서다. 여러 경로는 랙 사이의 통신 용량을 높이고 혼잡을 분산하는 데도 도움이 된다.

</details>

## 7. 웹페이지 요청 전체 흐름

### Q29. 노트북을 네트워크에 연결한 뒤 웹 서버의 IP 주소를 알아낼 때까지 어떤 일이 일어나는가?

<details>
<summary>정답 보기</summary>

1. **DHCP**로 자신의 IP 주소, 서브넷, DNS 서버, 기본 게이트웨이 정보를 받는다.
2. **ARP**로 기본 게이트웨이의 MAC 주소를 알아낸다.
3. DNS 질의를 게이트웨이로 보내고, **DNS** 응답을 통해 웹 서버의 IP 주소를 알아낸다.

</details>

### Q30. 웹 서버의 IP 주소를 알아낸 뒤 웹페이지를 받기까지의 흐름을 설명해 보자.

<details>
<summary>정답 보기</summary>

클라이언트는 서버와 TCP 3-way handshake를 수행해 연결한다. 브라우저가 HTTP GET 메시지를 만들면 `HTTP 메시지 → TCP 세그먼트 → IP 데이터그램 → 링크 계층 프레임` 순서로 캡슐화되어 전달된다. 서버는 요청을 처리한 뒤 같은 계층 구조를 이용해 HTTP 응답을 돌려준다.

## 학습 내용 요약

링크 계층은 네트워크 경로 전체가 아니라 **서로 인접한 두 노드 사이의 전달**을 담당한다. IP 데이터그램을 프레임으로 캡슐화하고, 현재 링크에 맞는 MAC 주소를 사용해 다음 노드로 전달한다. 프레임을 전송하는 과정에서는 패리티, 체크섬, CRC 같은 방법으로 오류를 검사한다.

여러 노드가 하나의 채널을 공유하면 충돌할 수 있다. 이를 해결하기 위해 채널을 시간·주파수·코드로 나누거나, ALOHA와 CSMA처럼 전송 시점을 조정하거나, 폴링과 토큰 전달로 차례를 정한다. 현대의 스위치 기반 이더넷은 호스트마다 독립된 링크를 제공하므로 일반적으로 충돌이 없다.

LAN 안에서는 MAC 주소로 프레임을 전달하며, ARP가 같은 서브넷의 IP 주소와 MAC 주소를 연결한다. 다른 서브넷으로 보낼 때 현재 프레임의 목적지 MAC 주소는 기본 게이트웨이의 주소다. 라우터를 지날 때마다 프레임과 MAC 주소는 바뀌지만 최종 목적지 IP 주소는 유지된다.

스위치는 출발지 MAC 주소를 보고 포트를 자가학습하고, 라우터는 IP 주소를 보고 서로 다른 네트워크를 연결한다. VLAN은 하나의 물리적 네트워크를 여러 논리적 LAN으로 나누며, MPLS는 레이블을 이용해 전달 경로를 효율적으로 관리한다.

웹페이지 요청의 큰 흐름은 **DHCP → ARP → DNS → TCP → HTTP**다. 링크 계층은 이 과정에서 생성되는 데이터를 각 링크에 맞는 프레임으로 포장해 다음 노드까지 운반한다.
